## Main menu redesign

Only the look changed. Gameplay, scoring, map generation and hazards are untouched.

- **Live map behind the menu.** At start-up (and whenever the menu comes back) the menu draws a separate round-3 city with its waiting groups and starting fires, dimmed with `BUILDING_DIM` under a 55% scrim. The map view's own fire, safe-zone and marker animations keep it moving. The backdrop has its own random generator, so `--seed=N` replays are unchanged, and no round runs under it. START DISPATCH still builds a fresh round 1 map.
- **Control-unit card.** The menu is a framed box like the side panel, with a **DISPATCH UNIT** title strip, a blinking amber **STANDBY** LED and `UiWidgets.Screw` casing screws in the corners.
- **Best score LCD.** A **BEST SCORE** module shows the stored best on a `UiWidgets.Lcd` with the round reached, or `----` / "NO RUNS YET" before the first finished run.
- **START DISPATCH** replaces START GAME. It uses the DISPATCH button style and the original mint/white pulse (off when `JUICE_ENABLED` is false). SETTINGS stays as the second button.
- **Settings card.** Same framed box with a **SETTINGS / CONFIG** strip, a **MASTER VOLUME** module, a palette-coloured slider (dark track, teal fill, mint fader cap drawn in code) and the volume level on an LCD. END GAME and BACK sit side by side; END GAME still appears only in-game.
- **Polish.** One logo (shown at exactly 2x) instead of logo plus a duplicate "EVAC GRID" label. The menu now sits under the scanline overlay and tablet frame, so the scanlines show over it. The menu fades out over 0.3 s when a round starts.
- **Tests.** `test_generation.gd` has a new `[main menu]` test: backdrop kept separate from the round, START gives a fresh round 1, the fade, END GAME/BACK from both entry points, MAIN MENU return and the best-score LCD.
- **Validation.** `test_generation.gd -- --seeds=1`: 40,431 checks, 0 failures. `test_city_layout.gd -- --seeds=1`: 25,512 checks, 0 failures.

## Team controls and UI

## Round endings and scoring

- Automatic game over from casualties occurs only when deaths exceed all survivors still alive in the round.
- If no safe route remains, the next round is available only when saved people strictly outnumber lost people; equal saved/lost numbers are game over.
- When no safe route remains, survivors in waiting or blocked groups are counted as trapped/lost before the ending decision.
- No-safe-route endings use the full score breakdown panel.
- Added **VIEW MAP**, **NEXT ROUND**, and **MAIN MENU** choices to the no-route ending.
- Viewing the map now exposes a **ROUND OPTIONS** button that reopens the ending panel.
- Updated the score breakdown text to match the new round-completion rule.
- Added regression coverage for trapped groups when no safe route remains, including the equal saved/lost game-over case.
